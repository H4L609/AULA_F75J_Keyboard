# AULA F75J 出荷時ファームウェア 解析資料

このプロジェクトの基本資料。人間にも AI にも読めるように、事実と推測を分けて書く。

- **確認済み**: このフォルダの `backup/` にある実機のダンプで、自分たちで確かめたこと
- **F75 由来**: 英語配列版 F75 の解析（[Thaolia/smk_aulaF75](https://github.com/Thaolia/smk_aulaF75) の `docs/keyboards/aula-f75.md`）に書かれていて、F75J ではまだ確かめていないこと

アドレスはすべて 16 進数で書く。

---

## 1. 本体の識別

| 項目 | 値 | 根拠 |
|---|---|---|
| チップ（MCU） | SinoWealth SH68F90A（8051 系） | 確認済み（下の USB ID と起動用領域が一致） |
| USB ID | `258A:010C` | 確認済み（Windows のデバイス一覧、ファーム内の `0x5FC6` にある USB 識別情報） |
| メーカー名の文字列 | `BY Tech` | 確認済み（`0x5E65`） |
| 製品名の文字列 | `AULA F75 JIS` | 確認済み（`0x6027`） |
| 無線チップ | Beken BK3632（EUART0 でつながる） | F75 由来 |
| 2.4GHz 受信機の USB ID | `3554:FA09` | 確認済み（Windows のデバイス一覧） |

書き込みツール sinowisp では、`-d aula-f75` でこの機種を指定できる。

## 2. フラッシュメモリの構成（全 64KB）

| 範囲 | サイズ | 中身 |
|---|---|---|
| `0x0000`–`0xEFFF` | 61,440 バイト | ファームウェア本体。書き換えるのはここ |
| `0xF000`–`0xFFFF` | 4,096 バイト | 起動用プログラム（ISP ブートローダ）。**書き換えない** |

- ブートローダの md5 は `3e0ebd0c440af5236d7ff8872343f85d`。sinowisp の対応表に載っている F75 の値と同じ（確認済み）。
- 電源を入れると、まずブートローダが動く。ファーム本体の入口（`0xEFFB` に置かれたジャンプ命令）が有効なら、本体に処理が移る（sinowisp の説明と F75 由来の情報）。
- sinowisp で読み出すと、`0x0001`–`0x0002` の 2 バイトは本来の値と入れ替わった形で保存される。ダンプの先頭はメモリの中身そのままではない、と覚えておくこと（sinowisp の説明）。

バックアップ:

| ファイル | 中身 |
|---|---|
| `backup/F75J_firmware.hex` | 本体（`0x0000`–`0xEFFF`） |
| `backup/F75J_full.hex` | 全体（ブートローダを含む）。Arduino で戻すときに使う |

## 3. キーの読み取り（マトリクス）

キーは「列を 1 本ずつ選んで、行の電気を読む」方式で読み取っている。

### 3.1 端子の初期設定（確認済み、`0xA7F5`）

```
P0CR=9C  P1CR=3F  P2CR=3F  P3CR=3F  P4CR=4D  P5CR=87  P6CR=FF  P7CR=60
```

ビットが 1 の端子は出力、0 の端子は入力。値は F75 とまったく同じ（F75 では `0xA7EC` にあると書かれている。日本語配列版は少し後ろにずれている）。

### 3.2 行（6 本、確認済み、`0x6F53` と `0x6F79`）

| 行 | 端子 |
|---|---|
| r0–r3 | P7.0–P7.3 |
| r4–r5 | P5.3–P5.4 |

読み取りの命令は F75 とまったく同じ（`mov a,P5 / add a,ACC / anl #30 / … / mov a,P7 / anl #0F / orl / orl #C0`）。

### 3.3 列（17 本、確認済み、切り替え表は `0x6E95`）

20 か所ある切り替え表のうち 17 か所が使われている。それぞれの処理は「前の列を戻して、次の列を選ぶ」だけをする。

| 列 | 端子 | | 列 | 端子 |
|---|---|---|---|---|
| c0–c7 | P6.0–P6.7 | | c12 | P4.0 |
| c8 | P5.0 | | c13 | P4.2 |
| c9 | P5.1 | | c14 | P4.3 |
| c10 | P5.2 | | **c15** | **P4.5** |
| c11 | P5.7 | | **c16** | **P4.6** |

- **英語配列版との違い**: F75 は 15 列（c14 = P4.3 まで）。日本語配列版は c15 と c16 が増えている。
- c16（P4.6）には ¥ キーがある。P4.6 は出荷時の設定で出力になっている。
- c15（P4.5）にはキーがなく、出荷時の設定では入力。F75 の解析では、P4.5 は「接続方式の切り替えスイッチ」の端子とされている。列としては空振りしているとみられる（推測）。

### 3.4 ノブ（確認済み、`0x7932`）

回転は P0.5 と P0.6 の 2 本で読む（`mov a,P0 / swap / rrc / anl #03`）。F75 と同じ。ノブを押すと、キー表の r0 c14 に入る。

## 4. キー表

### 4.1 場所と並び（確認済み）

| 層 | 先頭アドレス |
|---|---|
| ベース層 | `0xCC00` |
| Fn 層 | `0xD000` |

- 1 キーあたり 4 バイト（`b0 b1 b2 b3`）。
- 並び順は `番号 = 列 × 6 + 行`。17 列なので 102 キー分（408 バイト）。
- 実際の割り当ては [f75j-matrix.md](f75j-matrix.md) を参照。

### 4.2 4 バイトの意味

| b0 | 種類 | b1 | b2 | b3 | 例 |
|---|---|---|---|---|---|
| `00` | 普通のキー | 修飾キー（ビットの組み合わせ） | – | HID キーコード | `00000004` = A、`00040000` = Alt、`0004002B` = Alt+Tab |
| `02` | メディアキー | – | 用途コード（上位） | 用途コード（下位） | `020000E9` = 音量 +、`02000223` = ブラウザのホーム |
| `07` | 特殊機能 | – | – | 機能番号 | `07000005` = Bluetooth 1 |
| `08` | ライトの設定 | 種類 | 値 | 値 | `08030100` = 明るさ + |
| `0D` | Fn キー（押している間 Fn 層になる） | – | – | – | `0D000000` |

修飾キーのビット: `01` = 左 Ctrl、`02` = 左 Shift、`04` = 左 Alt、`08` = 左 Win、`20` = 右 Shift（標準の USB の並びと同じ）。

### 4.3 特殊機能（b0 = `07`）の番号

`0x412C` で番号ごとに処理を振り分けている。振り分け表（`0x4139`、17 件）は F75 と同じ（確認済み）。
処理の中身は、自作の逆アセンブラ（[tools/dis8051.py](../tools/dis8051.py)）で読んだ。

| 番号 | 処理の場所 | 中身 | 置き場所 |
|---|---|---|---|
| `00` | `4170` | 何もしない | – |
| `01` | `417D` | **Win キーのロック**を切り替える（`29h.6`）。Windows モードのときだけ効く | Fn + Win |
| `02` | `41A0` | **全キーのロック**を切り替える（`29h.5`、推測）。このロック中は、ほかの特殊機能がすべて止まる | 置かれていない |
| `04` | `41B3` | **工場出荷時に戻す**（長押しを数える） | Fn + Esc |
| `05` `06` `07` | `41C8` ほか | **Bluetooth 1 / 2 / 3** に切り替える | Fn + 1 / 2 / 3 |
| `08` | `426A` | **ペアリングのやり直し**（長押しを数える）。2.4GHz モードのときだけ効く | Fn + 半/全 |
| `0A` | `428A` | 約 8 秒後に、無線チップへ命令 `04`（値 `3`）を送り、ライトを点ける。命令の意味は不明 | Fn + G |
| `0B` | `42A0` | **ライトのオン / オフ**（`23h.3`） | 置かれていない |
| `11` | `42B1` | 無線のときだけ、数字キーの列（1〜0）を決まった色で光らせる。**電池の残量表示**と推測 | Fn + B |
| `18` | `4325` | **OS モード = 0（Windows）** | Fn + W |
| `19` | `4345` | **OS モード = 1（Android）** | Fn + Q |
| `1A` | `4366` | **OS モード = 2（Mac）** | Fn + E |
| `1B` | `4388` | OS モード = 3（不明。iOS か？） | 置かれていない |
| `1C` | `43AE` | 設定 `0x032D` の 0 と 1 を切り替える（意味は不明） | 置かれていない |
| `1D` | `43D5` | 長押しを数える（中身は未解析） | ノブ押し |

**メモ: OS モードの保存場所**
- OS モードはメモリ `0x0328` に入る（0 = Windows、1 = Android、2 = Mac）。マニュアルの「Fn + Q / W / E」と一致する。
- Win キーのロックが Windows モードでしか効かないことも、この解釈と合う。
- F75 の解析資料では、`0x0328` を「今の Bluetooth の接続先」と推測している。しかし上の処理を読むかぎり、OS モードとみるのが正しい。

**メモ: 「置かれていない」機能について**
出荷時のキー表のどこにも置かれていない機能でも、処理そのものはファームの中に残っている。

## 5. 無線（2.4GHz / Bluetooth）

### 5.1 結論

**F75J の無線の仕組みは F75 と同じ**とみてよい。F75 の解析で手がかりになった部分が、F75J のダンプでもすべて同じ形で見つかった。違ったのは、アドレスが少しずれていることと、Bluetooth の名前だけ。

### 5.2 仕組みの概要（F75 由来）

- メインチップ（SH68F90A）と無線チップ（BK3632）は、シリアル通信（EUART0、約 260,870 bps）でつながっている。
- キーを押したときの情報は「フレーム（決まった形の枠）」に入れて無線チップに送る。枠の 0 バイト目は `01`、1 バイト目がコマンド。
- 無線チップからの返事の最後の 1 バイトは、`0x55 − ほかのバイトの合計` で計算される確認用の値。
- 無線で使っている間は USB が止まる。そのため CapsLock のランプの状態を受け取れない。

### 5.3 F75 と照らし合わせた結果（確認済み）

| 手がかり | F75 | F75J |
|---|---|---|
| シリアル受信の割り込み（番号 13） | あり | あり（`0x006B` → `0xA54D`） |
| シリアル割り込みを最優先にする設定（`IPH1=42`, `IPL1=41`） | `0xECC5` | `0xEDDA` |
| 無線チップへの送信処理 | `0xAB0F` | `0xAB18` |
| キー情報の送信（長さ 30） | `0x46C2` | `0x46BE` |
| メディアキーの送信（長さ 13） | `0x4730` | `0x472C` |
| Bluetooth 名の送信（長さ 32） | `0xA376` | `0xA3EA` |
| まとめ送り（長さ 23） | `0xB0B8` | `0xB0BF` |
| 短いコマンド（長さ 6） | `0xED53` | `0xED30` |
| 作業用メモリの番地（`0x08B2`, `0x09BD`, `0x097E`, 送信待ちの `0x0C57`） | 使用 | 同じ番地を使用 |

送信処理を呼ぶ 5 か所は、送る長さ（30 / 13 / 32 / 23 / 6）まで完全に一致した。

### 5.4 Bluetooth の名前（確認済み、`0xAF1B`）

| 名前 | 用途（推測） |
|---|---|
| `AULA F75 JIS 3.0` | Bluetooth 3.0 用 |
| `AULA F75 JIS 5.0` | Bluetooth 5.0 用 |

自作ファームにするときは、この名前に合わせておくとわかりやすい。

## 6. ライト（RGB LED）

### 6.1 結論

**LED はキーと同じ「行 × 列」の並び**で光らせている。そのため日本語配列版では、キーと同じく **6 行 × 17 列**になる。各キーの LED の番号は、キー表と同じ `列 × 6 + 行` になる。例えば ¥ キーの LED は 97 番（列 16・行 1）。

### 6.2 光らせ方（F75 由来、F75J でも一部確認済み）

- キーを読むときと同じように、列を 1 本ずつ選ぶ。その列にある 6 行ぶんの LED の色を、PWM（明るさを細かく調整できる出力）18 本で一度に出す。18 本の内訳は、6 行 × 赤・緑・青。
- この方式では、どの瞬間も、選ばれている 1 列だけが光っている。列を高速に切り替えるので、全体が光って見える。

| PWM の出力 | 担当する行 | 端子 |
|---|---|---|
| 0–5 | 行 0, 1（赤緑青 × 2） | P1.0–P1.5 |
| 6–11 | 行 2, 3 | P2.0–P2.5 |
| 12–14 | 行 4 | P3.3–P3.5 |
| 15–17 | 行 5 | P3.0–P3.2 |

- 色の作業用メモリ: 8 ビットの色を `0x0152 + 列 × 18 + 行 × 3 + 色` に置く。それを 16 ビットに直したものを `0x05A2 + 列 × 36 + …` に置く。
  - F75J でも、`0x765B` に同じ計算（`列 × 18 + 0x0152`）があることを確認済み。
- 端子の初期設定（`P1CR`、`P2CR`、`P3CR` = `3F`）も F75 と同じ（3.1 を参照）。

### 6.3 列数が 17 であることの裏付け（確認済み）

- ライトの効果を描く処理の中に、「列の番号を 1 つずつ増やして 17 になったら終わる」という繰り返しが 18 か所あった（`0x5BF9`、`0x62D7`、`0x64E2`、`0x66EA` など）。
- 「17 まで」の比較は 23 か所見つかった。「15 まで」の比較は 1 か所しかなく、それも列の処理ではなかった。

### 6.4 自作ファームへの影響

- F75 向け移植版の LED 処理は 15 列で作られている。これを 17 列に増やす必要がある。
- c15（P4.5）は入力に設定されているので、この列の LED は光らない。キーもないので困らない。

## 8. 自作ファームにするときに必要なこと

F75 向けの SMK 移植版を土台にする場合:

1. **列を 15 から 17 に増やす**（P4.5 と P4.6 を加える）。キーの読み取りと LED の両方で必要。
2. **日本語配列の配置を足す**（[f75j-matrix.md](f75j-matrix.md) の表のとおり）。
3. 書き込む前に、**Fn + B のような「USB に頼らずにブートローダに戻る方法」**が自作ファームに入っているかを確かめる。失敗したときの逃げ道になる。
